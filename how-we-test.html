How we test

Research, catalogue validation and hands-on testing are different evidence layers. We label them separately.

Research-based pages

These pages use official documentation, current policies, plan pages and independent editorial benchmarks. They can explain fit, cost and risk but do not claim measured performance.

Catalogue validation

Automated feeds are filtered by active programme, exact URL, title relevance, excluded terms, duplicate detection and minimum quality thresholds. Weak matches remain hidden.

Hands-on testing

A page is labeled hands-on only when TrendPilot has used the product with a documented test method. The method, device, version and test limitations should be visible.

Software test pattern

Use the same representative project, record completion time, export restrictions, premium prompts, stability and the steps that caused confusion.

Hardware test pattern

Define compatibility, repeated starts, connection stability, calls, delay, heat, firmware path and return-window checks before naming a winner.
